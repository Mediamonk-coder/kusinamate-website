returns an inquiry reference, and browser retains details and blocks repeat
same-page submissions. Slack acceptance means HTTP acceptance, not human receipt.
Legacy Supabase/Basin/n8n submissions are removed in prepared code only. Existing
backend records/services are untouched. Recipe reads unchanged.

MAINTAINABILITY TRADEOFF (NO NEW SERVICES)
No database, durable queue or retry service introduced. Duplicate prevention is
same-page only; reloads, new tabs and manual repeated submissions can duplicate.
No durable reconciliation or replay endpoint. Unknown network outcomes are never
automatically retried. Known partial success never triggers whole-request retry.
There is no exactly-once guarantee. Durable cross-session deduplication would
require an approved persistent store and a separate design; it is not necessary
for this simple send-once implementation and has not been introduced.
